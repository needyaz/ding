# Delta: Tests that can fail for five behaviors Ding's recovery found unguarded

- Unit: ding
- Delta id: ding-20261109-3
- Status: proposed

## What changes

Ding's baseline recovery (2026-11-09, `spec/DRIFT_REPORT.md` section 4) found tests that pass whatever the code does. Five of them guard behavior that matters:
- **DING-CTRL-016, privacy:** what AI assistants may see. The test feeds an empty event list, so it cannot fail.
- **DING-MCP-003:** CRLF input from MCP clients. `serve` trims only spaces and tabs, so a trailing carriage return reaches the JSON parser, and the test only counts output lines, which a parse-error reply also produces. This one is likely a real bug.
- **DING-HOTKEY-001:** hotkeys off by default. The test checks nothing about hotkeys.
- **DING-MENUBAR-003:** the bell glyph's clapper. The test passes even when the clapper is fused to the lip.
- **DING-IPC-008:** the socket path length. The test measures a path it builds itself instead of the real one.

This change gives each a test that fails when the behavior breaks, and fixes the code where the stronger test exposes a bug. All five rows end as C.

## Requirements

| id | change | statement |
|---|---|---|
| DING-CTRL-016 | modify | Assistants see only the events left after calendar selection and dropdown filters: an event in a hidden calendar, a declined or canceled event, and (with those toggles off) an event without a meeting link or an unconfirmed one never appear in what the control service returns. |
| DING-MCP-003 | modify | Input lines with surrounding spaces, tabs or a trailing carriage return are parsed as the message they contain: each gets the same successful reply as the trimmed line, never a parse error (-32700). |
| DING-HOTKEY-001 | modify | There are two global hotkeys, Open Ding menu and Join next meeting, recorded on the Shortcuts tab and off until the user records a shortcut: with fresh defaults neither has a shortcut. |
| DING-MENUBAR-003 | modify | The bell's clapper is drawn separate from its lip so it survives at small sizes: in the rendered template image there is a fully transparent gap between the clapper and the lip at the menu bar size. |
| DING-IPC-008 | modify | The real socket path, `DingIPC.socketURL` for an app-group container path shaped like the real one, fits in sockaddr_un's sun_path including the terminating NUL. |

## Acceptance criteria

- DING-CTRL-016: a hosted test builds the model with fakes (as the existing control-service tests do), with a visible event plus one of each excluded kind, and asserts the control service's list holds exactly the visible one. It also shows each excluded kind appears once its own toggle allows it, where a toggle exists.
- DING-MCP-003: Tests/DingMCPTests feed lines with leading and trailing spaces, tabs, and a trailing `\r` through `serve`, and assert each reply is the successful result for that request, not -32700. If `serve` lets `\r` through today, fix the trimming in Sources/DingMCP.
- DING-HOTKEY-001: a hosted test with isolated defaults asserts both hotkey names have no shortcut. It uses the KeyboardShortcuts API the app already uses.
- DING-MENUBAR-003: a test renders the menu bar glyph at the menu bar's point size and scale 2, then finds a row or column of fully transparent pixels separating the clapper's pixels from the lip's. The clock hands do not count as the gap: the test's comment says which region is the clapper.
- DING-IPC-008: a test calls `DingIPC.socketURL` with a container path as long as a real one (`/Users/<a 32-character name>/Library/Group Containers/<team>.blue.luci.Ding`), and asserts its UTF-8 byte length plus one fits in `MemoryLayout.size(ofValue: sockaddr_un().sun_path)`.
- The weak tests named in DRIFT_REPORT.md section 4 for these five ids may be strengthened in place rather than duplicated. Existing test names stay.
- Bundle IDs, the app group, entitlements and signing do not change.

- Settled by the owner (accepted from hardening):
  - Declined and canceled events are covered by the fact that CalendarStore.map returns nil for them, so they can never become a DingEvent; the DING-CTRL-016 test feeds a hidden-calendar event, an unconfirmed event and an event without a link, and the declined and canceled clause is not tested through the control service.

- DingTests/PreferencesTests.swift: only "testHotkeysAndAlertsAreOffByDefault" changes, to also assert the hotkeys.

- Tests/DingMCPTests/EndToEndTests.swift: only "testLinesWithSurroundingWhitespaceAreAccepted" and "testAWindowsLineEndingIsAccepted" change, to assert the reply.
